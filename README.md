# 测款神器 · Product Click Sample Calculator

一个用于电商选品和投放前规划的桌面可视化工具：根据预计购买率、观测可信度和允许的相对误差，测算至少需要多少有效访问样本，帮助评估产品转化表现所需的数据量。

## 主要功能

- 调整观测可信度 `a`、允许上下浮动比例 `r` 和预计真实购买率 `p1`。
- 自动计算最低测试人流量，并将样本量向上取整。
- 展示预计购买人数、购买率参考范围和对应购买人数范围。
- 展示计算依据，支持恢复默认参数和复制完整计算结果。
- 使用 Python / Tkinter 实现本地桌面界面，无需账号或联网服务。
- 包含 Windows 打包脚本、macOS Universal2 打包脚本及现有双系统交付包。

## 补充说明：这个模型帮你解决什么问题？

### 先用一句话理解

**测新品、测视频时，先算一算大概要给多少流量，观察到的反馈率才不容易被偶然的好坏带偏。**

如果一次要测试很多商品或视频，每个都花钱投放，流量给少了可能误判，给多了又会增加测试成本。这个工具帮助你提前规划测试所需的流量，让不同产品、不同内容的比较更有依据。

### 为什么不能只看前几十次浏览？

可以把它想成抛一枚公平硬币：正面概率是 50%，但只抛 10 次，可能出现 7 次正面，也可能只有 3 次。这不代表硬币的真实概率变成了 70% 或 30%。

商品和视频也一样。前几十个访客恰好很喜欢，或者恰好都没兴趣，都会让结果显得特别好或特别差。在受众、投放方式等条件保持稳定时，流量越多，观察到的比例通常越稳定，但不会保证每增加一次浏览都更接近真实水平，也不能消除所有不确定性。

### 三个容易混淆的概念

| 名称 | 普通人的理解 | 例子 |
| --- | --- | --- |
| 观测反馈数据 | 本次测试实际拿到的反馈。本模型计算时使用的是反馈率。 | 100 次有效访问产生 4 次购买，观测购买率就是 4%。 |
| 真实反馈率（这里说的“真实数据”） | 某个商品或视频在特定人群和投放条件下，长期表现所对应的概率。它通常无法被直接知道，只能通过样本估计。 | 某商品在这些条件下，每次有效访问的购买概率可能是 3%，短期观察值却会上下波动。 |
| 优秀对标值 | 同类目优秀商品或视频的表现，用来设定测试目标或估算输入参数。 | 平台显示同类优秀商品购买率约为 3%，可以先以 3% 作为规划参考。 |

**优秀同行的数据是参考目标，不能直接当成你自己的商品或视频的真实水平。** 即使是平台给出的同行指标，本身也可能受到样本量、统计周期和流量来源的影响。

这里的反馈不局限于购买，也可以是点击、收藏、点赞、加购等。每次计算先选定一种指标，并保持统计口径一致：

- 测点击率：用展示次数作为样本，记录每次展示是否带来点击。
- 测购买率：用有效访问作为样本，记录每次访问是否带来购买。
- 测点赞、收藏或加购率：先明确分母是播放、曝光还是访客，再按同一口径记录是否发生对应行为。

本模型适合这种“发生 / 没发生”的比例指标，各次样本还应尽量独立。重复访客、同一用户反复操作可能让有效样本量低于表面流量。播放时长、客单价，以及同一次访问中可重复累计的评论条数等，不能直接套用这套公式。不同反馈率也应分别测算，不能简单相加成一个比例。

### 软件里的六个参数和结果，分别是什么意思？

当前界面以“购买”为例。用于其他反馈指标时，可以把“购买”对应理解为所选的点击、点赞、收藏或加购行为。

| 项目 | 是输入还是结果？ | 怎么理解 |
| --- | --- | --- |
| 观测可信度（也可称观察可信度） | 输入 | 你希望测试结果有多稳定。越高，通常需要的流量越多。它描述模型假设成立时重复测试的统计把握程度，不是“这个款有多大概率是爆款”。 |
| 允许上下浮动 | 输入 | 你愿意接受观测反馈率相对预计真实反馈率偏离多少。例如以 3% 为基准、允许 ±20% 浮动，得到 2.4%～3.6%，不是 3% 上下各加减 20 个百分点。 |
| 预计真实购买率 | 输入 | 你事先假设或参考对标数据设定的购买概率。原描述中的“预计真实购买量”，在当前模型中应理解为“预计真实购买率”；人数则是算出来的结果。 |
| 建议测试人流量 | 结果 | 在上述假设和精度要求下，建议积累的最低样本数。测点击率时应对应展示量，测购买率时应对应有效访问量，不能一律理解成广告点击量。 |
| 预计购买人数 | 结果 | 建议样本量乘以预计购买率，表示假设成立时平均预期的购买人数；不代表保证会成交这么多人。 |
| 可信范围 | 结果 | 当前界面的“p2 可信范围”是预计反馈率按允许浮动得到的参考区间，不是根据本次实际反馈数据算出的置信区间。 |

### 用一笔实际测试来理解

假设你准备测试一款新品，参考同类优秀商品，先设定：

- 预计真实购买率：**3%**。
- 允许上下浮动：**±20%**。
- 观测可信度：**80%**。

工具算出的建议测试人流量是 **1,328 人**。如果该商品在这些投放条件下的真实购买率确实约为 3%，这批访问平均预期会产生 **约 39.8 次购买**，购买率参考范围是 **2.4%～3.6%**，对应当前界面显示的 **32～47 人**。

80% 可以这样理解：**如果真实购买率确实为 3%，且样本独立、条件稳定，反复进行许多轮这样的测试，按本模型的正态近似，大约 80% 的测试轮次，其观测购买率会落在 2.4%～3.6% 附近。** 单独这一轮仍可能落在范围之外；软件也没有据此算出“有 80% 概率成为爆款”。

如果你更希望结果稳定，就提高可信度；如果你希望误差更小，就缩小允许浮动。两者通常都会增加需要的测试流量。

### 实际应该怎么用？

1. **选定反馈指标。** 这次看购买率，还是点击率、点赞率？先明确分子、分母和统计周期。
2. **设定参考水平。** 结合历史数据、同类优秀对标和自己的投放条件，填写预计反馈率。
3. **确定精度要求。** 设置可信度和允许浮动，查看建议测试流量，再据此安排预算。
4. **积累反馈并进行比较。** 尽量保持流量来源、人群、价格、素材和投放时段可比，避免把不同条件的数据混在一起。

**这个工具负责回答“为了观察转化表现，大概要准备多少样本”。** 达到建议流量后，还要结合实际观测反馈、对标水平、利润或内容目标做判断。当前软件没有录入实际反馈、进行优劣检验或自动判定爆款的功能；改变对标水平、反复中途查看结果，也不等于已经完成统计验证。

## 计算方法与适用范围

采用二项分布的正态近似进行样本量规划：

```text
z = 标准正态分布在 (1 + a) / 2 处的分位数
m = ceil(z² × (1 - p1) / (r² × p1))
购买率参考范围 = p1 × (1 ± r)
```

公式中的 `a`、`r` 和 `p1` 使用小数形式；界面中输入百分数。

这个工具计算的是估计购买率所需的样本量。它没有读取实际订单、计算实际观测数据的置信区间或自动判定“爆款”。界面中的“p2 可信范围”由输入的预计购买率及允许浮动直接生成，用于规划参考。

“人流量”应使用与购买率分母一致的有效访问或独立访客口径；如果使用广告点击量，应先核对重复点击与访客的统计口径。实际测款时应尽量保持流量来源、价格、素材和投放时段可比。样本少或购买事件少时，正态近似存在局限。

## 从源码运行

建议使用 Python 3.10 或更新版本，并安装带 Tk 支持的 Python。

```bash
python app.py
```

应用运行只使用 Python 标准库，不需要额外的 pip 运行依赖。

## 测试

```bash
python -m unittest -v test_app.py
```

现有测试覆盖默认 3% 购买率、12% 购买率和部分无效参数。

## 打包与交付

### Windows

```powershell
python -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

输出为 `dist/StyleTestTool.exe`。`make_icon.py` 生成图标时优先使用 Windows 微软雅黑字体。

### macOS

在 Mac 上安装带 Tk 和 Universal2 支持的 Python，然后执行：

```bash
zsh build_macos.sh
```

脚本会创建构建虚拟环境，生成 Universal2 应用并执行本地临时签名，输出 `dist/测款神器-Mac-universal.zip`。脚本会清理当前项目下的 `build/` 和 `dist/`。未包含 Apple Developer ID 签名或公证流程。

### 已有交付包

仓库中的 `测款神器-双系统交付版.zip` 为本地已有的 v1.0 双系统交付归档，内含 Windows EXE、Mac DMG 和使用说明；本次归档没有重新构建安装包。
